# Open source contribution

## Overview

I am Ana, a software engineering student, and this project documents my first contribution to a public repository. I chose a small issue because I wanted to understand the full contribution flow without taking on a large change on my first attempt. I spent three evenings on the task, with about two hours per evening, and I kept notes on each step so I could review what I learned afterward. I contributed a documentation fix to an open source project on GitHub.

## What I did

I started by reading the project’s contribution guide and comparing the current documentation with the reported issue. The problem was simple: one section described a setup step in a way that could confuse new contributors. I reviewed the surrounding text, checked how the same step was described in other parts of the repository, and wrote a clearer version of the paragraph.

My work was limited to:
- identifying the confusing sentence
- rewriting it with the same meaning but clearer order
- checking the change for consistency with the rest of the file
- preparing a short explanation for the submission

I also had to learn how to create a clean change set and how to respond to review comments. The first version I submitted was too brief, so I expanded the explanation to make the intent of the change easier to understand.

## Results

The change was accepted after one round of review. The maintainer asked for a small wording adjustment, which I made the same day. After that, the change was merged into the main branch. The final result was one improved documentation section and a better understanding of how public collaboration works.

This first contribution gave me a concrete example of:
- reading requirements carefully
- making a small but useful improvement
- accepting feedback without changing the scope of the task

## Challenges and learnings

The hardest part was not the edit itself, but understanding what level of detail was expected. I initially tried to explain too much, which made the paragraph less direct. I learned that in shared documentation, clarity matters more than completeness when the audience is trying to follow a step quickly.

I also learned that even a small contribution can take time because of reading, verification, and review. For me, the most useful lesson was that a first contribution does not need to be large to be meaningful; it just needs to solve one real problem carefully.
